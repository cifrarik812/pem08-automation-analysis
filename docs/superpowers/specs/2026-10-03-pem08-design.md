# PEm08: анализатор сервисов автоматизации

## Цель и исходная база

Учебная адаптация https://github.com/Toxap/pem08, исходный коммит 14e826dc639ae777fc3eb7abb088d6a952fcedd6. Ниша подтверждена пользователем: n8n, Make, Albato. Продукт сравнивает публичные материалы и дизайн их страниц, сохраняя источник, дату и ограничения выводов.

## Решение

Сохраняем FastAPI, веб-интерфейс, Selenium и клиент PyQt6 из урока. Для анализа текста и изображений используем существующий GigaChat: OpenAI/ProxyAPI у пользователя не настроены. Это явное отклонение от пункта задания о провайдере; работа выполняется в Codex по ранее разрешённому подходу, не приписывается Cursor. Альтернативы: исходный ProxyAPI требует нового ключа; анализ без API не проверяет весь пайплайн и не выбран.

## Данные и контракт

В data сохраняются снимки трёх публичных страниц и manifest с URL, датой и SHA256. Анализ JSON содержит наблюдения, ограничения, рекомендации, automation_fit, design_score (0–10 или null при отсутствии изображения), animation_potential (гипотеза, не утверждение о работающей анимации). Сведения о цене/надёжности не выводятся из отсутствия текста на одном снимке. Каждый ответ проходит строгую проверку схемы; неправильный JSON возвращает ошибку, а не пустой успешный ответ.

## Поток

Текст или файл → проверка ввода → GigaChat → проверка JSON → результат и история. Парсер принимает только три заданных публичных домена, собирает видимый контент и снимок → та же логика анализа → история. Не обходим проверки сайтов и не используем авторизованные браузерные профили. История содержит полные результаты, времена и источник, хранится локально отдельно от учебной истории автора.

## Конфигурация и сборка

Ключ остаётся во внешнем существующем .env и никогда не включается в репозиторий/EXE. TLS включён. Сервер слушает только localhost. Исходная desktop-сборка является клиентом отдельного backend, что отмечаем прямо; проверяем запуск EXE и реальную операцию через него. Новый аккаунт, покупка или смена настроек старых проектов не требуются.

## Проверка готовности

Тесты валидации JSON, плохого файла, ограничений URL, истории, ошибок API. Реальные анализы текстов и изображений трёх конкурентов; проверка Selenium, сохранённой истории, Web UI и EXE. Если внешний сервис недоступен, фиксируем факт, не называем его пройденным тестом. README, обезличенные результаты, промпты, снимки, отчёт. Публичную публикацию GitHub выполняем только после подготовки и проверки файлов и подтверждения конкретного репозитория. На учебной платформе сохраняется только черновик, анкета не заполняется.
